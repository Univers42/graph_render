# review-gates — can any gate in `graph-cli` exit 0 when it should not?

Reviewed `origin/develop` @ `9af0ccb` (job start). Read-only: no code changed.
Scope: `crates/graph-cli/src/**` (the gates), `scripts/scigraphs-conformance.sh`,
`harness/scigraphs-conformance*`. Rules of record: `prompts/jobs/review-core-post.md`,
`CLAUDE.md` "House limits", `prompt.md` §6.

The question per gate is the one the job body sets: **what input makes it exit 0 when it
should not** — a skipped arm counted as a pass, a timeout read as success, an empty
comparison set, a tolerance that admits any value, a fingerprint that misses a path the
result depends on, a negative control that cannot turn red. Exit contract under review:
**0 passed, 1 ran and failed, 2 could not run**; any other mapping is a finding.

Method: 24 `explore` subagents, one per module slice, dispatched in batches of four to
twenty; every BLOCKER and MAJOR below was then re-verified by me against the source, and
nine of them were reproduced by a command run in this job. The scratch harnesses used for
those reproductions were written into the tree, run, and removed;
`git status --porcelain` is empty at the time of writing.
