## 0. What this phase was

Edge geometry as a stage of its own. The reference is explicit that this is a separate
stage — layout returns positions, every edge-path concern lives downstream — which is
exactly why every algorithm here composes with every layout without new code, and why this
is a motor rather than a collection of renderers. The phase also exists because `.sgraphs`
stores no edge path data at all, so bundling and routing output there vanishes; the
`Polyline` and `Curve` kinds exist so this stage's output survives serialization.

## 6. Ponytail markers added

Four, as the phase requires. Two are in the `post::POSTS` metadata (in code, not yet in the
ledger, §2); two are in the module docs and the measurement files.

- **FDEB is an approximation controlled by a compatibility threshold.** Failing input:
  edges just below the threshold that a viewer would expect bundled. Direction:
  under-bundling — cosmetic. Escape hatch: the threshold parameter. `Bundled::unbundled`
  counts the edges that merged with nothing, so the number is in the output.
- **MINGLE is greedy** — a non-optimal bundle hierarchy. Cosmetic.
- **Grid routing's resolution is a trade.** Failing input: a gap narrower than one cell.
  Direction: a detour, or a fallback to a straight line through a node — visually wrong,
  the dangerous direction — plus the flag that reports it. **The measurement moved this
  marker's mechanism, and the ledger text says so rather than leaving the reader to infer
  it:** `phase08-routing.md` §4 swept the gap from 8 cells to none and found **no
  fallbacks at any width, including a gap of zero cells**, because `margin: 2` extends the
  grid two cells past the drawing so a route always has somewhere to go. The measured
  mechanism is **enclosure, not gap width**. The Ponytail stands as written; the
  measurement refines it.
- **No marker on the style generators** — exact arithmetic, no threshold, no sampling, no
  fallback, no estimate, every point computed once in `f64` and cast once.
  `post::styles::ledger.rs`'s own text says exactly this, and adds the two conventions it
  does owe (the self-loop's half-radius lift, the L/Z corner rule).

**Spatial pruning is not ported, and its absence is its own marker.** The prompt says "use
the Phase-8 grid index to limit candidate pairs spatially if the measurement demands it, and
record that as a deviation with its number". The measurement did not demand it — FDEB's
pair count is quadratic (5 341 at 100 nodes → 5 051 209 at 3 200) and the ceiling is set
from that, but no spatial pruning was added. `phase08-ink.md` states it: "FDEB is `O(m^2)`
to build the pair list; **the reference's spatial pruning is not ported**". The prompt's
"if spatial pruning was added, its error is a second marker" is therefore **not
applicable** — a second marker that was never owed.
