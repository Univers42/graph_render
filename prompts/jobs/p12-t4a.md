# Job p12-t4a (agent build, the 3D arms of five closed-form and spectral SciGraphs names)

Why: the user wants every SciGraphs layout exactly as SciGraphs computes it (2026-09-30). The coverage table
(`docs/measurements/scigraphs-coverage.md`) marks six names "on develop (2D port)". The motor answers only the
2D question for them, but SciGraphs returns 3D. This job ships the 3D arm of five of them:

| SciGraphs name | function | 2D id on develop | new id |
|---|---|---|---|
| `RANDOM` | `_random_layout` `basic.py:5` | `layout.random` | `layout.random.3d` |
| `SPIRAL_3D` | `_spiral_layout_3d` `basic.py:36` | `layout.spiral` | `layout.spiral.3d` |
| `BIPARTITE_3D` | `_bipartite_layout_3d` `hierarchical.py:213` | `layout.bipartite` | `layout.bipartite.3d` |
| `SPECTRAL_3D` | `_spectral_layout_3d` `networkx_layouts.py:249` | `layout.spectral` | `layout.spectral.3d` |
| `MDS_3D` | `_mds_layout_3d` `networkx_layouts.py:271` | `layout.mds.pivot` | `layout.mds.pivot.3d` |

All paths are under `SciGraphs/core/scigraphs_core/mesh/layouts/`. Read each function, never recall it.

Precondition: `p13-3d` is on develop, so the snapshot carries `dim` and a z column
(`docs/decisions/contract-3d.md` and `contract-3d-verdict.md`). Check with
`git grep -n dimension-3d crates`. If it finds nothing, stop and report.

The model to follow is `prompts/jobs/p12-t3.md`: its register-and-gate facts, its determinism rules and its
per-layout deliverables (module, full `Metadata`, hashgate pinned record, ledger routing, differential,
measured ceiling, negctl) all apply. The differences:
- Each 3D arm reuses its 2D kernel. The dimension is a parameter of one kernel, not a copy: extract before
  the second copy (`spectral.rs:29-31` holds `DIMS: usize = 2`, and it becomes the argument).
- Every 2D id must keep byte-identical output. Before any edit, run the golden sweep
  (`graph-cli snapshot --seed s --layout l --out-bin - | sha256sum` for every `layout.*` and seeds 0..7) into
  `target/golden-before.txt`. Run it again at the end; the diff on the 2D ids must be empty.
- The oracles already exist and gain a dim argument: `oracle-closed-form` (networkx 3.6 `random_layout`,
  `spiral_layout` and `bipartite_layout` at `dim=3`, with the SciGraphs arm wherever SciGraphs adds its own z) and
  `oracle-spectral` (SciGraphs `_spectral_component_coordinates` and `_pivot_mds_component_coordinates` at 3
  dims on scipy 1.16.2). Ceilings are measured, never widened. A row that misses its ceiling stays
  `Status::Implemented`, with its measurement written down.
- Append the five entries at the end of `LAYOUTS`.
- In the coverage table, each row gets its 3D id and the status "on develop (2D and 3D)". Update the counts.

Paths: the five kernels and their registry files, the closed-form and spectral oracle harnesses and their
graph-cli subcommands, the hashgate pinned record, capabilities routing, `graph-wasm/src/exports/build.rs`,
`scripts/orch/rows/p12-t4a.rows` (new), `docs/measurements/p12-t4a.md` (new) and the coverage table.

Done when: the golden diff for the 2D ids is empty, the five 3D ids pass `registry/tests.rs`, each differential
has run at 1000 seeds with its gap and ceiling recorded, the negctls exit non-zero, and quick.rows is green.
