Why: the user asked for every SciGraphs layout to be in the motor AND in the studio picker
(`prompts/RESUME.md`, "Queued, not started"; `prompts/jobs/scigraphs-gap.md:3-5`). The picker reads
the motor's registry, so registering a layout IS the delivery — there is no second list to keep in
sync. These five are the last `missing` rows in the coverage table
(`docs/measurements/scigraphs-coverage.md:61`, "missing = 5, all of them 3D": `SPRING_3D`, `SPHERE`,
`HELIX`, `CUBE`, `HIERARCHICAL_3D`). The whole group sits behind one prerequisite — the 3D contract

Facts:
- SciGraphs side. Every path below is under
  `SciGraphs/core/scigraphs_core/mesh/layouts/`, and every claim is read from that file, not from
  memory.
  - `SPRING_3D`: `dispatcher.py:57` selects `_spring_layout_3d`, defined `networkx_layouts.py:26` — a
    thin wrapper over networkx 3.6 `spring_layout` at `dim=3`.
  - `SPHERE`: `dispatcher.py:101` selects `_sphere_layout`, `basic.py:22`. Fibonacci sphere;
    latitudes sit at the band midpoints `(i+0.5)/n`, angle `theta = pi*(3 - sqrt(5))*i`. Its docstring
    cites Gonzalez 2010 and Marques et al. 2013, so the formula is not a house invention.
  - `HELIX`: `dispatcher.py:107` selects `_helix_layout`, `basic.py:65` (def spans `basic.py:65-80`).
    A double helix: `levels = (n+1)//2`, angle `t*4*pi + (i%2)*pi`, radius `scale*0.3`, z
    `t*scale*2 - scale`. An odd node count leaves the extra node on strand 0.
  - `CUBE`: `dispatcher.py:109` selects `_cube_layout`, `basic.py:83`. Eight hard-coded corners in a
    fixed order, then the remainder scattered strictly inside from `_get_layout_rng()`. A single node
    returns the origin.
  - `HIERARCHICAL_3D`: `dispatcher.py:111` selects `_hierarchical_layout_3d`, `hierarchical.py:113`
    (def spans `hierarchical.py:113-147`). Roots are the in-degree-0 sources for a digraph, else
    `_component_roots` (`hierarchical.py:31`); levels come from a `_multi_source_levels` BFS
    (`hierarchical.py:54`); `_group_by_level` is `hierarchical.py:83`; per level
    `z = (level / max(1, max_level)) * scale * 2 - scale` and
    `radius = scale * 0.5 * sqrt(count / widest)`; the in-plane fill is `_disk_positions(count,
    radius)` at `hierarchical.py:90` — evenly spaced concentric sub-rings whose ring count is
    `round(sqrt(count/pi))`, all rings sharing `arange(rings)+0.5`, ring radius
    `r = radius*(k+0.5)/rings`.
  - `simulation.py` and `interactive.py` are NOT reachable from `dispatcher.py` (its only entry is
    `apply_graph_layout`). `interactive.py` re-implements the same name-to-function table twice more,
    at `interactive.py:24` and `interactive.py:452`, so those tables are a copy of the dispatch
    surface, not a second set of layout names. Do not read them as layout names.

4. `HIERARCHICAL_3D` (`_hierarchical_layout_3d`, `hierarchical.py:113`, def spans
   `hierarchical.py:113-147`). The most intricate of the four non-force layouts and the only one that
   reads the graph: roots from in-degree-0 sources, else `_component_roots` (`hierarchical.py:31`);
   `_multi_source_levels` BFS (`hierarchical.py:54`); `_group_by_level` (`hierarchical.py:83`); per
   level `z = (level / max(1, max_level)) * scale * 2 - scale` and
   `radius = scale * 0.5 * sqrt(count / widest)`; in-plane fill `_disk_positions(count, radius)`
   (`hierarchical.py:90`) with `round(sqrt(count/pi))` rings sharing `arange(rings)+0.5` and
   `r = radius*(k+0.5)/rings`. Complexity is O(n+m) for the BFS plus O(n) for the fill. Same seven
   deliverables. Two things the metadata must settle, not assume: the `widest` denominator when the
   graph has one level (the reference divides by `max(1, max_level)` for z, and the disk radius needs
   the same guard), and the BFS tie-break order, which is a D2 fixed-order requirement — say which
   dense index breaks a level tie. A cycle in the digraph, or a component with no in-degree-0 source,
   is the `Ponytail:` failing input: name it, name the direction (unreached nodes stay at the origin
   and pile up, which is visible and cosmetic; it never produces wrong-but-plausible spacing), and
   name the escape hatch.

   escape hatch (the iteration count is an explicit parameter, and the recorded hash is pinned to the
