# Job p12-t4b (agent build, the 3D arms of the force SciGraphs names)

Why: the same as `prompts/jobs/p12-t4a.md` (read it first; its precondition, golden sweep and rules all apply).
SciGraphs runs these force layouts in 3D by default, and the motor has only 2D ports of them:

| SciGraphs name | function | 2D id | new id |
|---|---|---|---|
| `FORCEATLAS2` | `_forceatlas2_layout` `forceatlas.py:150` (`dim=3` default) | `layout.forceatlas2` | `layout.forceatlas2.3d` |
| `YIFAN_HU` (`sfdp_dim` 3 and 2Z) | `_yifan_hu_layout` `yifan_hu.py:344` | `layout.force.yifan_hu` | `layout.force.yifan_hu.3d` |
| `IGRAPH_FR` | `igraph_layouts.py:53` (`'dim': 3`) | `layout.force.fruchterman_reingold` | `….3d` |
| `IGRAPH_KK` | `igraph_layouts.py:85` (`'dim': 3`) | `layout.force.kamada_kawai` | `….3d` |
| `IGRAPH_DRL` | `igraph_layouts.py:281` (`'dim': 3`) | `layout.force.drl` | `….3d` (`DRL_2D` stays on the 2D id) |

Precondition: `p13-3d` and `p12-igraph` are both on develop. `harness/oracle-igraph.py` exists and
`git grep -n dimension-3d crates` finds a hit. Otherwise stop and report.

- One kernel per algorithm, with the dimension as its parameter. For Barnes-Hut in 3D, the tree becomes an
  octree behind the same interface. Also read `docs/decisions/live-force-session.md` and keep the 2D
  `Session` bits unchanged.
- YIFAN_HU's `2Z` mode (a 2D layout that SciGraphs then lifts on z) is read from `yifan_hu.py` and ported as
  that source defines it, under the id `layout.force.yifan_hu.2z`.
- Oracles: `oracle-fa2` (networkx 3.6 at `dim=3`), `oracle-igraph` at dim 3, and stress for yifan_hu. Ceilings
  are measured and never widened; a row that misses stays `Status::Implemented`, with the measurement written down.
- Rows: `scripts/orch/rows/p12-t4b.rows`. Measurements: `docs/measurements/p12-t4b.md`. Flip the coverage-table rows.

Done when: the same bar as p12-t4a, for these ids.
