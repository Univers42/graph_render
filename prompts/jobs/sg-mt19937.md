# Job sg-mt19937 (agent build, SciGraphs conformance: RANDOM, CUBE)

Read `prompts/jobs/sg-common.md` first. Rows: `RANDOM` (cause `rng`, f32 0/1020) and `CUBE`
(`rng`, f32 501/1020: the eight corners already land, the interior does not).

Why: both rows draw from `np.random.RandomState(981798123)` on the reference side and from
graph-core's Mulberry32 on the motor side, so equal seeds are not equal draws. 981798123 is
`get_layout_seed()` = `derive_seed(42, "layout")`, `LAYOUT_SEED` in the conformance module.
- `RANDOM`: `basic.py:5-9`, a fresh `RandomState(seed).rand(n, 3) * scale`, row-major
  (x0, y0, z0, x1, ...). Motor: `layout/random.rs` draws two Mulberry32 values per node at
  `SEED = 0x00_5EED`, 2D, no scale.
- `CUBE`: `basic.py:83-103`; corners as now, then the interior is
  `rng.uniform(-1.0, 1.0, (m, 3)) * (scale * 0.8)` with `rng = _get_layout_rng()`, which
  `dispatcher.py` resets to a fresh `RandomState(get_layout_seed())` before every layout call
  (`_reset_layout_rng`, `dispatcher.py:22`). Motor: `layout/basic_3d/cube.rs` interior uses
  Mulberry32 at `SEED = 0x00_C0BE`. Its module doc says only the first call after a reset is
  reproducible; with the reset per call that is wrong: fix the sentence.

The generator, to port exactly (numpy legacy `RandomState`, `_mt19937.pyx` + `legacy-distributions.c`):
- integer seed s (0 <= s < 2^32): `init_genrand(s)`, i.e. `mt[0] = s`,
  `mt[i] = 1812433253 * (mt[i-1] ^ (mt[i-1] >> 30)) + i` (u32 wrapping), standard MT19937 twist
  and tempering;
- `rand()` = `random_sample`: `a = next_u32() >> 5`, `b = next_u32() >> 6`,
  `(a * 67108864.0 + b) / 9007199254740992.0`;
- `uniform(lo, hi)` = `lo + (hi - lo) * rand()`, evaluated in that order.
